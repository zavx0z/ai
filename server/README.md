# HTTP Server

Композиция публичных инструментов без собственного предметного runtime.
`index.ts` запускает HTTP-host, `request` владеет обработкой запроса,
`discovery` раскрывает package identity, exports, локальные контракты и сценарии.

Внешний транспорт: GET /tools и POST /tools. JSON-оболочка:
`{node?: string, action?: string, input?: object}`. Без `action` запрос только
описывает выбранный узел; единственное исполняющее действие — `run`.
Версии в URL и отдельного MCP SDK нет. Подробные примеры — в корневом README.

`request/src/bindings.ts` — явная сборка функций, а не второй каталог описаний.
Пути и контракты принадлежат пакетам; включение функции в exports само по себе
не делает её удалённо исполняемой. `server/request`, `server/discovery` и фабрики
контекста нельзя запустить через этот HTTP-вход.

Токен обязателен для чтения и записи. Нет wildcard CORS, произвольного импорта,
автоматического shell execution или повторного запуска операции при обрыве
соединения. `requestId` связывает ответ с JSONL-диагностикой без записи содержимого
input. Лимиты вводятся до выполнения функции.

Сценарии HTTP живут в `request/spec/`; структурные и dependency boundary проверки —
в `discovery/spec/`. Прогон под Node включает настоящий временный loopback listener.
Порт пользовательского процесса, Wazy SDK и UI-клиент не используются тестами.
