# 📝 AI Markdown Standards

Этот документ описывает строгий стандарт написания Markdown-документации для AI-ассистентов.

**Контекст:**

* **Автоматическая генерация:** AI генерирует Markdown-контент.
* **Линтинг:** Все документы проходят проверку markdownlint.
* **Стиль:** Используется стиль "compact" для таблиц.

---

## 1. Таблицы

### 1.1. Форматирование разделителей

Разделитель таблицы **обязан** иметь пробелы с обеих сторон от дефисов.

**✅ Правильно:**

```markdown
| Колонка 1 | Колонка 2 |
| --------- | --------- |
| Значение  | Значение  |
```

**❌ Неправильно:**

```markdown
| Колонка 1 | Колонка 2 |
|----------|----------|
| Значение  | Значение  |
```

### 1.2. Выравнивание контента

Контент в ячейках таблицы **должен** быть отделен от границ (pipe) пробелами.

**✅ Правильно:**

```markdown
| Значение | Описание |
| -------- | -------- |
| 1        | Первый   |
```

**❌ Неправильно:**

```markdown
|Значение|Описание|
|-------|-------|
|1|Первый|
```

### 1.3. Многострочный контент в ячейках

**⛔ Запрещено:** Использовать inline HTML (`<br>`) для переносов строк внутри ячеек таблицы.

**✅ Альтернативы:**

1. **Текстовые разделители:** Использовать точку с пробелом или точку с запятой.
2. **Нумерация:** Использовать цифры с точкой внутри текста.
3. **Разделение на строки:** Вынести сложный контент за пределы таблицы.

**Пример:**

```markdown
❌ Неправильно:
| Действие | Описание |
|----------|----------|
| Шаг 1    | Первое действие.<br>Вторая строка. |

✅ Правильно:
| Действие | Описание |
| -------- | -------- |
| Шаг 1    | Первое действие. Вторая строка. |
```

## 2. Списки

### 2.1. Нумерованные списки

**Правило:** Все элементы нумерованного списка **должны** начинаться с `1.` (стиль "1/1/1").

**✅ Правильно:**

```markdown
1. Первый пункт
1. Второй пункт
1. Третий пункт
```

**❌ Неправильно:**

```markdown
1. Первый пункт
2. Второй пункт
3. Третий пункт
```

### 2.2. Вложенные списки

Вложенные списки **должны** иметь отступ в 4 пробела.

**✅ Правильно:**

```markdown
1. Родительский пункт
    1. Дочерний пункт
    1. Еще один дочерний
```

### 2.3. Маркированные списки

Использовать звёздочку (`*`) для маркированных списков.

**✅ Правильно:**

```markdown
* Пункт 1
* Пункт 2
```

**❌ Неправильно:**

```markdown
- Пункт 1
- Пункт 2
```

---

## 3. Inline HTML

**⛔ Запрещено:** Использовать inline HTML-теги в Markdown-документах.

**Список запрещенных тегов:**

* `<br>` — использовать перенос строки (два пробела в конце строки или пустая строка)
* `<div>` — использовать блоки кода или цитаты
* `<span>` — использовать курсив или жирный шрифт
* `<a>` — использовать Markdown-ссылки `[текст](url)`

**Исключения:** HTML допустим только в случаях, когда Markdown не предоставляет альтернативы (например, специфические атрибуты для презентаций).

## 4. Заголовки

### 4.1. Иерархия

Заголовки **должны** следовать строгой иерархии без пропусков уровней.

**✅ Правильно:**

```markdown
# H1
## H2
### H3
```

**❌ Неправильно:**

```markdown
# H1
### H3 (пропущен H2)
```

### 4.2. Стиль

Использовать стиль `#` для заголовков, а не подчеркивание.

**✅ Правильно:**

```markdown
## Заголовок
```

**❌ Неправильно:**

```markdown
Заголовок
---------
```

---

## 5. Код

### 5.1. Блоки кода

Блоки кода **должны** иметь указание языка для подсветки синтаксиса.

**✅ Правильно:**

````markdown
```typescript
const x: number = 42;
```
````

**❌ Неправильно:**

````markdown
```
const x: number = 42;
```
````

### 5.2. Inline-код

Inline-код **должен** быть обрамлен обратными кавычками без пробелов внутри.

**✅ Правильно:**

```markdown
Функция `processData()` возвращает результат.
```

**❌ Неправильно:**

```markdown
Функция ` processData ` возвращает результат.
```

---

## 6. Пробелы и пустые строки

### 6.1. Пустые строки вокруг блоков

Блоки (заголовки, списки, таблицы, код) **должны** быть отделены пустыми строками.

**✅ Правильно:**

```markdown
## Заголовок

Текст параграфа.

* Пункт 1
* Пункт 2

Следующий параграф.
```

### 6.2. Конец файла

Файл **должен** заканчиваться одной пустой строкой.

### 6.3. Конец строки

Строки **не должны** содержать trailing spaces (пробелы в конце строки), за исключением случаев, когда два пробела используются для принудительного переноса строки.

---

## 7. Ссылки и изображения

### 7.1. Ссылки

Использовать inline-формат ссылок для коротких URL.

**✅ Правильно:**

```markdown
[Текст ссылки](https://example.com)
```

Для длинных URL использовать reference-формат:

```markdown
[Текст ссылки][ref]

[ref]: https://very-long-url.example.com/path/to/resource
```

### 7.2. Изображения

Изображения **должны** иметь alt-текст.

**✅ Правильно:**

```markdown
![Описание изображения](path/to/image.png)
```

**❌ Неправильно:**

```markdown
![](path/to/image.png)
```

---

## 8. Чек-лист перед генерацией

Перед генерацией Markdown-документа AI **обязан** проверить:

* [ ] Все таблицы имеют пробелы в разделителях
* [ ] Все таблицы имеют пробелы вокруг контента в ячейках
* [ ] Отсутствует inline HTML (`<br>`, `<div>`, `<span>`)
* [ ] Нумерованные списки начинаются с `1.`
* [ ] Маркированные списки используют `*` (звёздочку)
* [ ] Заголовки следуют иерархии без пропусков
* [ ] Блоки кода имеют указание языка
* [ ] Блоки отделены пустыми строками
* [ ] Файл заканчивается пустой строкой
