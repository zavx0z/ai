# Общие принципы README для разработки

## Основные правила

1. **Зафиксируй суть** — в трёх предложениях опиши, что делает проект и зачем он нужен
2. **Сохрани контекст** — запиши ключевые идеи, которые пригодится вспомнить через месяц
3. **Обозначь текущее состояние** — что работает, что в процессе, что сломано
4. **Сфокусируйся на концепциях** — описывай архитектурные принципы, а не код (код будет меняться)
5. **Пиши для себя и ИИ** — это внутренняя памятка, а не публичная документация

## Что должно быть в README

### Обязательно

- **Цель проекта** — зачем существует этот код
- **Текущий статус** — что сейчас в работе/завершено/планируется
- **Ключевые идеи** — основные архитектурные решения и подходы

### Опционально (по ситуации)

- Особенности работы с проектом (если есть нюансы)
- Известные проблемы и технический долг
- Контекст для ИИ-агента (особенности проекта, на что обращать внимание)

## Чего избегать

- Списки файлов и модулей
- Примеры кода (устареют)
- Команды запуска (меняются)
- Детальные инструкции (проект меняется)

## Формат

Кратко, тезисами, можно использовать неформальный язык. Это живой документ — редактируй по мере изменения проекта.
