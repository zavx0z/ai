# Правило для ИИ: Удаление мёртвого кода

## Цель

Очистить кодовую базу от неиспользуемых фрагментов, улучшая читаемость, поддерживаемость и производительность, не нарушая функциональности.

## Типы мёртвого кода (что искать)

1. **Неиспользуемые переменные, параметры, импорты**
   - Локальные переменные, которые нигде не читаются.
   - Параметры функций, не используемые в теле.
   - Импорты модулей/типов, которые нигде не применяются.

2. **Неиспользуемые функции, классы, константы**
   - Экспортируемые сущности, которые никем не импортируются.
   - Внутренние функции/константы, не вызываемые/не используемые в файле.

3. **Недостижимый код (unreachable code)**
   - Код после `return`, `throw`, `break`/`continue` в циклах.
   - Условные ветки, которые никогда не выполняются (например, `if (false) { ... }`).

4. **Пустые блоки**
   - Пустые функции, циклы, условия без содержимого.

5. **Заглушки и обратная совместимость**
   - Экспорты-алиасы для обратной совместимости, которые уже не нужны.
   - Комментарии с пометками `TODO`, `FIXME`, если они больше не актуальны (по согласованию).

6. **Неиспользуемые зависимости (package.json)**
   - Пакеты, которые не импортируются ни в одном файле проекта.

## Принципы удаления

### 1. **Не навреди**

- Убедись, что код действительно не используется. Проверь:
  - Поиск по проекту (grep, IDE) упоминаний имени сущности.
  - Анализ экспортов: если сущность экспортируется, проверь, импортируется ли она в других файлах.
- Не удаляй публичный API библиотек, если не уверен, что он не используется внешними потребителями.

### 2. **Удаляй целые блоки, а не строки**

- Если удаляешь функцию, удаляй всё её объявление целиком (включая тело).
- Если удаляешь импорт, удаляй всю строку импорта (или соответствующий элемент из деструктуризации).

### 3. **Сохраняй форматирование и структуру**

- После удаления блока кода убедись, что не осталось лишних пустых строк или синтаксических ошибок (например, висящих запятых).
- При удалении последнего импорта из блока удаляй и сам блок, если он пуст.

### 4. **Действуй итеративно и проверяй**

- После каждого удаления запускай сборку/тесты, чтобы убедиться, что ничего не сломалось.
- Если проект использует линтер (ESLint), он часто подсвечивает мёртвый код — используй это.

## Процесс для AI Patcher (JSON-формат)

При выполнении задачи "удали мёртвый код" следуй этому алгоритму:

1. **Сканируй файлы** (список предоставлен пользователем или весь проект).
2. **Идентифицируй мёртвый код** по описанным выше категориям.
3. **Для каждого найденного фрагмента** подготовь операцию `replace` или `delete` в формате AI Patcher:
   - `file` — абсолютный путь к файлу.
   - `action` — `replace` (замена на пустую строку или изменённый блок) или `delete` (по сути то же, но replace с пустой строкой).
   - `search` — точный блок кода для удаления (с сохранением оригинальных пробелов и переносов, экранированных как `\n`).
   - `replace` — либо пустая строка, либо новый код (если требуется корректировка, например, удаление элемента из списка импортов).
4. **Группируй операции** по файлам, чтобы минимизировать количество изменений.
5. **Убедись, что изменения не пересекаются** (например, удаление функции и её вызова в одном файле лучше делать одной операцией, заменяя весь блок, или последовательно).
6. **Проверь синтаксис** итогового JSON и экранирование.

## Примеры

### Пример 1: Неиспользуемый импорт

**Было:**

```ts
import { foo, bar, unused } from './module';
console.log(foo, bar);
```

**Операция:**

```json
{
  "file": "/project/src/file.ts",
  "action": "replace",
  "search": "import { foo, bar, unused } from './module';",
  "replace": "import { foo, bar } from './module';"
}
```

### Пример 2: Неиспользуемая функция

**Было:**

```ts
function helper() {
  // никогда не вызывается
  return 42;
}

function main() {
  return 0;
}
```

**Операция:**

```json
{
  "file": "/project/src/file.ts",
  "action": "replace",
  "search": "function helper() {\n  // никогда не вызывается\n  return 42;\n}\n\n",
  "replace": ""
}
```

### Пример 3: Неиспользуемая константа

**Было:**

```ts
const DEAD_CODE = 123;
export const USED = 456;
```

**Операция:**

```json
{
  "file": "/project/src/file.ts",
  "action": "replace",
  "search": "const DEAD_CODE = 123;\n",
  "replace": ""
}
```

### Пример 4: Пустой блок

**Было:**

```ts
if (condition) {
  // ничего не делаем
}
```

**Операция:**

```json
{
  "file": "/project/src/file.ts",
  "action": "replace",
  "search": "if (condition) {\n  // ничего не делаем\n}\n",
  "replace": ""
}
```

## Важные замечания

- **Не удаляй код с побочными эффектами**, даже если результат не используется (например, вызов функции, которая модифицирует внешнее состояние). Такой код не является мёртвым.
- **Будь осторожен с TypeScript**: удаление типа может повлиять на типизацию. Убедись, что тип действительно не используется.
- **Учитывай динамические вызовы**: если функция вызывается через `eval`, `new Function`, или по строковому имени (например, в рефлексии), она может быть живой, даже если статический анализ не находит её использования.
- **Проконсультируйся с пользователем**, если сомневаешься в удалении экспортируемого API.

## Итоговый формат ответа

Ответ должен содержать JSON с описанием и массивом операций, как указано в инструкции AI Patcher.

```json
{
  "description": "Удаление мёртвого кода: неиспользуемые импорты и переменные",
  "operations": [ ... ]
}
```

Не добавляй никакого пояснительного текста вне JSON.
