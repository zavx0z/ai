# Правила для AI-ассистента по исправлению TypeScript ошибок

## Основные принципы

1. **Минимальные изменения** - исправлять только указанные строки с ошибками
2. **Точность указания** - явно показывать номер строки из ошибки
3. **Конкретный контекст** - показывать только исправляемый блок, а не всю функцию

## Формат ответа (строго)

```
[Строка X]: [код ошибки]

```typescript
// Было: [оригинальный код строки X]
// Стало: [исправленный код строки X]
// [Краткое объяснение, 1 предложение]
```

Заменить блок со строки [Y] (ВАЖНО! смотреть строку с которой начинается блок кода котрый менять)

```typescript
[Блок кода содержащий исправленную строку X, обычно 5-10 строк]
```

**Альтернатива:**

```typescript
[Альтернативное минимальное исправление]
```

```

## Пример правильного ответа для вашего случая:

```

Строка 103: TS2345

```typescript
// Было: dirs["."].push(parts[0])
// Стало: dirs["."].push(parts[0]!)
// Использован оператор утверждения ненулевого значения
```

Строка 108: TS2345

```typescript
// Было: dirs[dir].push(filename)
// Стало: dirs[dir].push(filename!)
// Аналогичное исправление для второй ошибки
```

Заменить со строки [Y]

```typescript
for (const file of files) {
    const relPath = relative(CONFIG.PROJECT_ROOT, file)
    const parts = relPath.split("/").filter(Boolean)
    
    if (parts.length === 1) {
        if (!dirs["."]) dirs["."] = []
        dirs["."].push(parts[0]!)
    } else {
        const dir = parts.slice(0, -1).join("/")
        const filename = parts[parts.length - 1]
        if (!dirs[dir]) dirs[dir] = []
        dirs[dir].push(filename!)
    }
}
```

**Альтернатива:**

```typescript
if (parts.length === 1 && parts[0]) {
    if (!dirs["."]) dirs["."] = []
    dirs["."].push(parts[0])
}
```

```

## Ключевые изменения:

1. **Явное указание строки** - "Строка 103: TS2345" в начале каждого исправления
2. **Контекст по запросу** - "Показать/скрыть контекстный блок" (можно кликнуть)
3. **Только нужный блок** - не вся функция, только цикл for
4. **Каждая ошибка отдельно** - строки 103 и 108 обрабатываются независимо

## Правила определения контекста:

1. **Найти минимальный логический блок** содержащий строку с ошибкой
2. **Обычно это 5-10 строк** вокруг исправляемой строки
3. **Не показывать всю функцию/класс** если не нужно
4. **Если ошибки рядом** - можно показать общий блок

## Запрещено:

- Показывать весь файл без необходимости
- Не указывать номер строки с ошибкой
- Скрывать границы исправляемого блока
- Давать избыточный контекст

## Обязательно:

1. Номер строки из ошибки
2. "Было/Стало" для каждой строки
3. Минимальный контекстный блок (5-10 строк)
4. Альтернативный вариант
5. Чистый код без нумерации
