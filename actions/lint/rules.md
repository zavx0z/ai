# Исправление TS ошибок

## Основные принципы

1. **Минимальные изменения** - исправлять только указанные строки с ошибками
2. **Контекст ошибки** - использовать предоставленный фрагмент кода (`context`) для точного определения места исправления. Если контекст содержит несколько строк, используйте их все для уникальности поиска
3. **Конкретный контекст** - показывать только исправляемый блок, а не всю функцию
4. **Обработка файлов** - правило может обрабатывать несколько файлов, для каждого указывается путь

## Формат ответа (строго)

```
[Путь к файлу] — [код ошибки]
```typescript
// Было: [оригинальный код из поля context]
// Стало: [исправленный код]
// [Краткое объяснение, 1 предложение]
```

**Контекст замены:**
Заменить блок со строки [Y] (ВАЖНО! смотреть строку с которой начинается блок кода который менять)

```typescript
[Блок кода содержащий исправленную строку X, обычно 5-10 строк]
```

**Альтернатива:**

```typescript
[Альтернативное минимальное исправление]
```

```

## Пример правильного ответа для нескольких файлов:

```
src/components/Button.tsx — TS2322
```typescript
// Было: const handleClick = (event: MouseEvent) => {
// Стало: const handleClick = (event: React.MouseEvent) => {
// Указан правильный тип события из React
```

**Контекст замены:**
Заменить блок со строки [10]

```typescript
const Button: React.FC<ButtonProps> = ({ onClick, children }) => {
  const handleClick = (event: React.MouseEvent) => {
    if (onClick) {
      onClick(event);
    }
  };
  
  return (
    <button onClick={handleClick}>
      {children}
    </button>
  );
};
```

---

src/utils/formatters.ts — TS2532
```typescript
// Было: return item.price.toFixed(2);
// Стало: return item.price!.toFixed(2);
// Добавлено утверждение ненулевого значения для price
```

**Контекст замены:**
Заменить блок со строки [38]

```typescript
export function formatPrice(item: Product): string {
  if (!item) {
    return '0.00';
  }
  
  // Проверяем наличие price перед форматированием
  if (item.price === undefined || item.price === null) {
    return '0.00';
  }
  
  return item.price!.toFixed(2);
}
```

**Альтернатива:**

```typescript
export function formatPrice(item: Product | null): string {
  return item?.price?.toFixed(2) || '0.00';
}
```

```

## Ключевые изменения для поддержки нескольких файлов:

1. **Указание пути к файлу** - "src/components/Button.tsx — TS1234"
2. **Разделение блоков через `---`** - визуальное разделение исправлений для разных файлов
3. **Поддержка разных расширений** - .ts, .tsx, .vue и другие TypeScript файлы
4. **Сохранение оригинальной структуры** - каждый файл обрабатывается независимо

## Правила работы с несколькими файлами:

5. **Уникальность контекста** - если строка кода встречается в файле несколько раз, расширяйте контекст поиска, добавляя предыдущие и последующие строки до тех пор, пока блок не станет уникальным

1. **Каждый файл — отдельный блок** исправлений с указанием полного пути
2. **Если ошибки в одном файле** - группировать в одном блоке под общим путем
3. **Порядок обработки** - по мере поступления ошибок или алфавитно
4. **Пути относительные или абсолютные** - в зависимости от контекста проекта

## Запрещено:

- Объединять исправления из разных файлов без разделения
- Пропускать указание пути к файлу
- Изменять код в файлах, не указанных в запросе
- Игнорировать расширения файлов (.ts vs .tsx)

## Обязательно:

1. Полный или относительный путь к файлу
2. Разделение исправлений по файлам через `---`
3. Указание расширения файла (.ts, .tsx, .vue и т.д.)
4. Независимая обработка каждого файла
5. Сохранение оригинальной структуры кода в каждом файле

## Особый случай — если путь не указан:

Если в исходном запросе не указаны пути к файлам, но есть несколько ошибок, можно использовать:

```
Файл 1 — [код ошибки]
(обработка как обычно)
---
Файл 2 — [код ошибки]
(обработка как обычно)
```

Или запросить уточнение: "Пожалуйста, укажите пути к файлам для каждой ошибки"
