### 🔎 **Правило: Целевой поиск элементов**

**Условие применения**: Пользователь *явно указывает список элементов* для поиска (например: `["send button", "chat input"]`).

#### 🔹 **Требования к анализу**:

1. **Ограничение зоны поиска**:
   — Анализировать *только* запрошенные элементы. Все остальные UI-компоненты игнорировать.
   — Если элемент не найден — **не включать** его в результат.

2. **Сопоставление запроса с интерфейсом**:
   — Искать элементы по **функциональному описанию**, а не по визуальным деталям:
     - Запрос `"send button"` → иконка самолёта/стрелки рядом с полем ввода.
     - Запрос `"user avatar"` → круглое изображение в углу экрана.
   — При неоднозначности (несколько кандидатов) выбрать элемент с **наибольшей логической связанностью** с контекстом интерфейса.

3. **Позиционирование**:
   — Координаты `(x_min, y_min, x_max, y_max)` нормализованы в диапазоне `[0.0, 1.0]`, где:
     - `(0.0, 0.0)` = верхний левый угол изображения,
     - `(1.0, 1.0)` = нижний правый угол изображения.
   — Значения округляются до **двух знаков после запятой** (например, `x_min: 0.91`, `y_max: 0.97`).

4. **Формат вывода**:

   ```json
   {
     "mode": "targeted_search",
     "requested_elements": ["string"],
     "found_elements": [
       {
         "query_match": "string",
         "name": "string",
         "type": "enum",
         "position": { "x_min": float, "y_min": float, "x_max": float, "y_max": float }
       }
     ]
   }
   ```

#### ⚠️ **Критические ограничения**:
— Нельзя добавлять элементы, не указанные в запросе.
— Нельзя угадывать скрытые состояния (выпадающие меню, анимации).
— Если запрос неоднозначен («кнопка» без контекста) → запросить уточнение у пользователя.
