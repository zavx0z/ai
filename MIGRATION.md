перенесён в `/Users/zavx0z/repozitarium/zavx0z/ai` с сохранением `main`, истории

самих инструментов сохранены. Описания генерируются штатным TypeDoc reader,
а HTTP использует готовый JSON без runtime-зависимости на reader или Storybook.

[Прикладной формат, подготовка описаний и граница хоста](DEVELOPMENT.md#http).
Привязка чата к назначенному контексту остаётся обязанностью внешней среды;
интеграция с чатами Storybook, WebSocket и прогресс не входят в этот этап.

# История выделения инструментов

## Основание

Замена содержимого `zavx0z/ai` выполняется поверх main
`aa9158b6055af2dc38c2ee3995f81147b7112e44`, без удаления истории.
Старые actions/UI/LLM-обёртки не входят в новое дерево; они остаются в родительском
коммите. Для отката после публикации нужен обычный git revert, а не force push.

Источники, сверенные для этого этапа:

- Interpreter `939dc8c020966ee6306b5036fbbc4864ad7e1d7c`:
  `packages/interpreter/src/workspace-tools.ts`, части `apply-patch.ts` и
  граница владельца в `module.ts`.
- Storybook `847071905f0828aa06599f9ad82f8dcca83f03e5`:
  AGENTS.md, нормативный вход структуры, размещение сущностей и контракты.

Это не заявление о повторном полном аудите всех репозиториев и историй.

## Исторический рабочий этап 15cc368

Реализованы 12 независимых файловых функций, Git status, структурное раскрытие
контрактов/сценариев и HTTP-host с явными bindings. У каждой функции есть input,
output и сценарий. Старый монолит workspace dispatcher не переносится в качестве
скрытого второго исполнителя. Источники Interpreter и Computer Use не изменены.

Новый публичный API намеренно отличается от старого workspace.*:
корни — явно настроенные aliases вместо абсолютных путей к прямым Git checkout;
обычные директории разрешены; переходы по symlink строже; read считает фактические
байты; patch отклоняет неоднозначность и повторные пути. Поэтому этот этап
не является drop-in заменой HTTP backend существующего Interpreter.

## Ещё не перенесено

`InterpreterModule`, `TargetSupervisor`, debugger connection, snapshots,
breakpoints, process restart, source-map resolution, source-edit/remap/replay
и событийная подписка UI остаются в Interpreter. Новых заглушек или упрощённого
процессного runtime вместо них нет. Сам Interpreter на новый HTTP-host не переключён.

Перед переносом runtime нужно извлечь полное замыкание зависимостей и исходные
тесты, затем сохранить bootstrap pause/autoresume, breakpoints между запусками,
точную идентичность модуля и изоляцию незатронутых модулей. Только после проверок
включать его структурные функции в bindings и переключать клиент.

Browser/CDP, browser-agent, browser_chat и UI space/focus не относятся к будущему
runtime-переносу в этот репозиторий. Дублирование Computer Use не создаётся.
