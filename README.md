# AI Tools

Самостоятельный монорепозиторий инструментов и HTTP-вход для Wazy MCP.
Сейчас исполняются **12 файловых инструментов и Git status**. Это первый
рабочий этап выделения возможностей Interpreter, не завершённый перенос
его debugger/runtime. Точное состояние — в [MIGRATION.md](MIGRATION.md).

## Структура

`filesystem/` владеет файловыми операциями, `git/` — Git status,
`server/` — структурным discovery и HTTP. У инструмента есть собственные
`index.ts`, `contract/input.ts`, `contract/output.ts` и `spec/scenario.spec.ts`.
Реализация находится в `index.ts`, помощники — в собственном `src/`, общие
механизмы — у ближайшего общего владельца в `shared/`.

Идентичность и публичные входы задаются `package.json`, `workspaces` и
`exports`. Контракты и сценарии не дублируются в MCP-каталоге. Storybook
не является runtime-зависимостью. Браузер, CDP, browser-agent и UI отсутствуют.

## Запуск

Нужны Bun либо Node.js 22.6+ и установленный Git для `git/status`.
Исполняемый код использует только стандартные модули; зависимости разработки
нужны для TypeScript-проверки.

```sh
bun install
export AI_TOOLS_ROOTS='{"project":"/absolute/path/to/checkout"}'
export AI_TOOLS_TOKEN="$(openssl rand -hex 32)"
bun run start
```

Альтернативный запуск без Bun: `npm run start:node`.
По умолчанию адрес — `http://127.0.0.1:8787/tools`.
`AI_TOOLS_HOST` и `AI_TOOLS_PORT` меняют явную конфигурацию слушателя.
`.env` автоматически не загружается. Не сохраняйте токен в репозитории.

`AI_TOOLS_ROOTS` — объект «короткий alias → абсолютная директория».
HTTP-клиент получает только alias и не может зарегистрировать новые корни.
Каталог не обязан быть Git checkout: это ограничение относится только к Git tool.

## HTTP-контракт

Нет `/v1`, `schemaVersion`, OpenAPI-реестра или отдельного stdio MCP-server.
`GET /tools` и `POST /tools` с `{}` возвращают обзор. Все запросы требуют
`Authorization: Bearer <token>`.

```json
{"node":"ai/filesystem/read"}
```

Такой запрос описывает инструмент, но ничего не читает из рабочего корня.

```json
{"node":"ai/filesystem/read","input":{"view":"contract"}}
```

Контракты возвращаются как исходный TypeScript. `view: "scenarios"` возвращает
исходник сценария с `executed: false`, а не выдуманный результат его выполнения.
Просмотр сценария не запускает тесты и не изменяет файлы.

```sh
curl --fail-with-body http://127.0.0.1:8787/tools \
  -H "Authorization: Bearer $AI_TOOLS_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"node":"ai/filesystem/read","action":"run","input":{"root":"project","path":"README.md","maxBytes":65536}}'
```

Выполнение требует явного `action: "run"`. HTTP-host подключает конкретные
публичные функции; структурный адрес никогда не превращается в произвольный
`import()`, shell-команду или путь исполняемого файла. Технические узлы сервера
могут иметь документацию, но не доступны для удалённого исполнения.

Wazy MCP должен передавать JSON-оболочку `{node?, action?, input?}` и заголовок
авторизации этому HTTP-host. Конкретный Wazy SDK, его конфигурация и живое
соединение с ним в этом этапе не проверялись.

## Ошибки и диагностика

Успешный ответ содержит непосредственно результат функции. Ошибка имеет форму:

```json
{"error":{"code":"NOT_FOUND","message":"The requested path does not exist"},"requestId":"..."}
```

HTTP различает неверный ввод (400), авторизацию (401), запрет доступа (403),
отсутствующий объект (404), конфликт (409), лимит (413) и внутренний сбой (500).
`PARTIAL_FAILURE` при ошибке I/O внутри patch содержит `details.completed`
и текущую операцию: это не обещание многофайловой транзакции.
Нативные ошибки прямых вызовов функций могут иметь системные коды; HTTP
нормализует их и не раскрывает абсолютные пути из сообщений ОС.

В stderr пишется JSONL: requestId, метод, узел, действие, статус, длительность
и код ошибки. Содержимое файлов, аргументы инструментов и токены не записываются.
Автоматических повторов изменяющих запросов нет. После потерянного ответа
сначала проверьте фактическое состояние файла.

## Границы безопасности

Сервис предназначен для доверенного владельца машины и доверенных рабочих
директорий. Токен даёт все опубликованные возможности, включая удаление.
Это **не OS sandbox**: нет защиты от враждебного локального процесса,
подменяющего предков пути между проверкой и системным вызовом. `expectedHash`
не является межпроцессной блокировкой.

Обход `..`, абсолютные пути, прямой доступ к `.git` и переходы через symlink
запрещены. `stat` может описать конечный symlink, `remove` — удалить саму ссылку.
Корень удалять/переименовывать нельзя. Рекурсивное удаление требует явного флага.
Чтение и записи ограничены 8 MiB, тело HTTP — 12 MiB. Для удалённого доступа
нужен отдельно настроенный TLS-транспорт; браузерные Origin-запросы не разрешены.

## Проверки

```sh
bun run check
bun test
# Независимый проверочный маршрут:
npm run test:node
```

Сценарии используют `node:test` и `node:assert/strict`, создают собственные
временные директории и не запускают операции на пользовательских корнях.
Есть проверка настоящего loopback HTTP-сервера. Локально выполнены TypeScript
и Node-сценарии; Bun-прогон и интеграция с Wazy не выдаются за выполненные.
